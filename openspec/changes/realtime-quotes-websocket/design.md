# Design

## Context

当前 0.2.x 的刷新链路：`qt.gtimg.cn` 单请求批量行情 + 任何被投递事件触发刷新（15 s 节流）+ 激活时数据陈旧（≥90 s）立即刷新。宿主只在插件 `Inactive` 时投递 `on-schedule`（`v0.1.39` `ide-host/plugins/mod.rs:2106` 要求 `status == Inactive`），因此面板可见时没有周期信号。

API 1.6（OpenIDEA 0.1.43）提供 host-owned WebSocket：`WebSocket::connect(project, {url, headers, subprotocol})`，`wss://` 只需 `net:<host>` 授权，每插件最多 8 条，`drain(limit)` 返回 `{messages, closed}`，`websocket-ready` 是普通事件（可唤醒 idle 插件），Drop 即关闭，队列溢出会拒绝新帧并关闭连接。

公开 WSS 行情端点在规划时**尚未证实**：对 `push2.eastmoney.com` / `qt.gtimg.cn` / `proxy.finance.qq.com` / `web.sqt.gtimg.cn` 根路径的握手探测均未返回 `101`。

## Goals / Non-Goals

**Goals:**
- 面板可见且用户静止时，报价仍能持续更新（秒级）。
- 实时通道不可用时无感退回现有轮询，报价不中断。
- 连接生命周期可控（按窗口、可关闭、可重连），不产生连接泄漏。

**Non-Goals:**
- 不更换行情供应商，不改 UI 结构。
- 不降低 `on-schedule` 的 60 秒声明（宿主限制，无意义）。
- 不承诺"零延迟"：只承诺"推送到达后 2 秒内反映到界面"。

## Decisions

### D1：升级到 `^1.6`，不追 `^1.8`
- **选择**：`engines.openidea = "^1.6"`，vendor 1.6 SDK。
- **理由**：1.6 是引入 WebSocket 的最小版本，IDE 门槛 0.1.43；1.8 只增调试器/文件图标能力，对本插件无价值。
- **备选**：`^1.8`（门槛 0.1.45，用户群更小）。

### D2：实时与轮询并存，而不是替换
- **选择**：WS 提供增量更新，轮询保留为兜底与冷启动。
- **理由**：WS 可能不可用（无项目、端点变更、协议不兼容）；冷启动仍需要一次批量快照。
- **备选**：纯 WS（无兜底，任一环节失败即无数据，不可接受）。

### D3：端点验证是硬门槛（阶段 0）
- **选择**：实施前必须完成"建连—订阅—收帧—解析"的最小验证；不通过则终止变更。
- **理由**：端点/协议是外部未知量，且可能非公开、随时变更；在未验证前写传输层是高风险投入。
- **备选**：直接按猜测实现（不可取）。

### D4：单连接复用
- **选择**：一个连接订阅全部自选股与指数，按代码路由帧。
- **理由**：远低于 8 条上限；减少握手与授权面。
- **备选**：每标的一条（会触及上限，否决）。

### D5：重连指数退避
- **选择**：1 s → 2 s → 4 s → … → 30 s 封顶，成功后重置；收到 `closed` 即重建。
- **理由**：避免断网时的紧密重试；宿主队列溢出会主动关连接，必须能自愈。

### D6：连接绑定窗口的 Project，无项目则降级
- **选择**：从 `Invocation::project()` 取项目；为 `None` 时不建连，只用轮询。
- **理由**：`WebSocket::connect` 要求 `borrow<project>`；插件在无项目窗口也应可用。
- **待确认**：`Invocation` 在所有事件/命令上下文中是否都带项目（实施时验证）。

### D7：合并策略按「行情时间」取新
- **选择**：推送与轮询写入同一 `Snapshot`；同一 symbol 比较 `Quote.ts`，较新者胜。
- **理由**：避免晚到的轮询覆盖较新的推送。

## Risks / Trade-offs

- **端点不存在或协议非公开** → D3 阶段 0 先验证；不通过即终止，保留 0.2.x。
- **协议随时变更** → 解析层容错（未知帧忽略）、失败即降级轮询；状态行可见提示。
- **IDE 门槛抬到 0.1.43** → 在 README/change-notes 明确；旧版 0.2.x 仍可安装。
- **wasm 体积继续增长** → 复用现有 `encoding_rs`；WS 层不引入新重依赖，构建后测体积。
- **多窗口重复连接** → 连接按窗口创建，单窗口单连接；关闭窗口即释放。

## Migration Plan

1. 0.3.0：`^1.6` + WS 增量 + 轮询兜底。
2. 升级用户首次运行会因 engines 变化被要求更新 IDE；0.2.x 不受影响。
3. 回滚：代码 `git revert`；已发布签名包不可改，只能发补丁版本；用户可继续装 0.2.x。

## 阶段 0 实测结论（2026-11-16）

| 候选 | 结果 |
|---|---|
| `wss://push2.eastmoney.com/webpush/` | **403**（4 种 Referer 与 `Sec-WebSocket-Protocol: webpush` 均 403） |
| `wss://push2delay.eastmoney.com/webpush/` | 403 |
| `wss://push2his.eastmoney.com/webpush/` | 403 |
| `qt.gtimg.cn` / `proxy.finance.qq.com` / `web.sqt.gtimg.cn` 根路径 | 200（非 101，不支持 WS） |

**结论：Gate 未通过，本变更终止。** 东财 WebSocket 依赖未公开的浏览器鉴权；腾讯不提供 WS。可继续成立的前提是存在以下之一：

1. 一个明确允许第三方客户端使用的公开 WSS 行情源（需提供端点与授权方式）；
2. 自建中继 + 宿主允许的 loopback 连接（`wit/io.wit` 注明 loopback `ws://` 仅用于测试，生产可行性未验证）；
3. 付费/官方 API 的 WS 通道（需提供凭据与条款许可）。

在此之前，保留 0.2.2 的轮询 + 事件心跳方案。

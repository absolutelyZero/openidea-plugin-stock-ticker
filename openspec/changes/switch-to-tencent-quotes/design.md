# Design

## Context

插件当前以 `wasm32-wasip2` 构建，SDK 为 vendor 的 API 1.3，`sync.rs` 用 `host::fetch` 请求东财 `push2` 的 JSON，`search.rs` 用东财 `searchapi` 的 suggest JSON。目标体积敏感（当前 wasm 约 331 KB）。

本次端点实测（2026-11-16，同一时段）：

| 端点 | 结果 |
|---|---|
| `push2.eastmoney.com` 批量 | `HTTP 000`，TLS 连接被中断 |
| `qt.gtimg.cn` 单只 | 200，540 B，0.11 s |
| `qt.gtimg.cn` 30 只 | 200，15,408 B，0.14 s，30/30 返回 |
| `qt.gtimg.cn` 连续 20 次 | 20/20 成功 |
| `smartbox.gtimg.cn/s3/?q=茅台` | 200，53 B，GBK，返回 `市场~代码~名称~拼音~类型` |

`qt.gtimg.cn` 与 `smartbox.gtimg.cn` 均返回 `charset=GBK`；数字字段为 ASCII，只有名称是中文。没有打开项目时插件仍可用（行情不依赖 `project.read`）。

## Goals / Non-Goals

**Goals:**
- 行情与检索统一走腾讯公开接口，移除东财依赖。
- 解析层对字段格式变化有明确边界：核心字段逐位核对、缺失或异常值不丢行。
- 网络能力从 5 项收敛到 4 项（`storage`、`events` + 2 个 `net:`）。
- 失败可见、不静默、不重试风暴。

**Non-Goals:**
- 不改刷新节奏、视图结构、命令集合与设置页结构。
- 不引入 WebSocket（API 1.6）或更低的 `on-schedule`。
- 不保留东财作为运行时兜底（按已确认的"彻底替换"范围）。

## Decisions

### D1：行情端用 `qt.gtimg.cn` 而非 `push2` 或 `hq.sinajs.cn`

- **选择**：`https://qt.gtimg.cn/q=<code,code,...>`，`~` 分隔文本。
- **理由**：单请求可覆盖 30+ 标的（实测 15 KB / 0.14 s），载荷远小于嵌套 JSON，解析为位置切分，无 JSON 解析开销。
- **备选**：东财 JSON（本次请求失败、载荷大）；新浪 `hq.sinajs.cn`（同样 GBK，但需要 `Referer`，额外约束）。
- **代价**：格式是位置契约，字段顺序变化会破坏解析 → 必须用真实样本做契约测试。

### D2：检索端用腾讯 JSON 检索接口，而非轻量 smartbox

- **选择**：`https://proxy.finance.qq.com/ifzqgtimg/appstock/smartbox/search/get?q=<query>`，读 `data.stock`（UTF-8 JSON，最多 50 条，每条 `[市场, 代码, 名称, 拼音, 类型, …]`）。
- **理由**：实测「银行」返回 50 条含中国银行/宁波银行等 `GP-A`；而 `smartbox.gtimg.cn/s3/` 对同一词只返回 10 条 ETF，`t=gp-a` 直接无结果，无法满足中文名检索。UTF-8 也省去检索链路的 GBK 解码。
- **备选**：`smartbox.gtimg.cn`（540 B 最轻，但宽泛中文词不可用）；东财 `searchapi`（与"彻底替换"范围冲突）。

### D3：GBK 解码优先 `encoding_rs`，以体积实测决定是否换方案

- **选择**：先用 `encoding_rs` 的 GBK 解码器把名称转为 UTF-8，构建后测量 wasm 体积增量。
- **理由**：这是唯一成熟、无维护负担的方案；数字字段不需要解码。
- **备选**：预生成"证券名称常用字"的 GBK 子集表（体积可控，但需要生成与维护）；或名称不解析、只显示代码（UX 退化，不采用）。
- **触发降级**：若体积增量超过约 60 KB，改为子集表，并在 tasks 中补一步体积对比。

### D4：市场前缀由代码规则推导

- **选择**：`6xxxxx`/`9xxxxx` → `sh`；`0xxxxx`/`3xxxxx`/`2xxxxx` → `sz`；`4xxxxx`/`8xxxxx`/`92xxxx` → `bj`；指数单独标记（`sh000001` 等）。
- **理由**：现有自选股以 6 位代码存储，无需新增字段。
- **风险**：北交所与特殊代码边界需用真实样本校验。

### D5：字段映射以真实样本为准，不在设计阶段写死索引

- **选择**：先从一段真实响应建立"索引 → 含义"映射表（名称、代码、现价、昨收、今开、成交量、时间、涨跌、涨跌幅），再落到解析代码；核心字段缺失时保留行并显示 `—`。
- **理由**：`~` 格式的索引位随接口版本可能变化，凭记忆写索引是最容易出错的地方。
- **验证**：契约测试直接内嵌一段真实响应片段，断言解析结果。

### D6：失败策略为"提示 + 保留上次数据"，不做自动重试

- **选择**：非 200、连接中断、`Denied` 三种情况都给出一次可见提示；保留上一次成功快照；下一个 15 s/60 s 周期再试。
- **理由**：避免失败风暴触发限流；符合 spec 的"失败可见"。

## Risks / Trade-offs

- **GBK 解码抬高 wasm 体积** → 先实测；超过阈值改子集表（D3）。
- **单一数据源** → 腾讯不可用时只能提示；缓解：错误信息明确、保留上次数据，后续可用 WebSocket（1.6）作为第二条通道。
- **位置式格式脆弱** → 用真实样本契约测试；解析失败时整批降级为错误提示而不是错位显示。
- **限流未知** → 保持 15 s 心跳不做激进调整；连续失败时按现有时间戳逻辑退避。
- **北交所/停牌/退市格式差异** → 用真实样本覆盖，异常值显示 `—` 而非丢弃。
- **能力变更属 BREAKING** → 升级说明与 README 明确"需要重新授权 2 个新 host"。

## Migration Plan

1. 版本 0.2.0；`plugin.toml` 的 `optional` 换成 2 个腾讯 host。
2. 构建、`check`、签名 `pack`，在 registry PR 追加 0.2.0 条目（保留 0.1.0 历史）。
3. 升级用户首次请求时 IDE 会提示授权新 host；拒绝则按 spec 提示，不崩溃。
4. 回滚：代码 `git revert`；已发布签名包不可改，只能发补丁版本；旧版 0.1.0 仍可安装。

## Open Questions

- `encoding_rs` 在本项目 release 配置（`opt-level="s"`、LTO、strip）下的实际体积增量，构建后测量即可确定，不影响本设计的选择。
- 腾讯接口在 5 秒级高频下的长期限流表现（本次仅 20 次样本）；本次不改间隔，后续单独评估。
